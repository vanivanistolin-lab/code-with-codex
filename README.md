# PhotoMaster AI

Локальная фотостудия на русском языке: FastAPI + React/TypeScript + Tailwind CSS + OpenCV/Pillow. Тёмный адаптивный интерфейс, загрузка до 20 фото, регулировка эффектов, интерактивное сравнение и ZIP с PNG/JPEG/WEBP.

## Быстрый запуск на Windows (PowerShell)

Требуются Python 3.12 и Node.js 22+ (LTS), Git. Все команды выполняются из корня проекта.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. API: `/docs`. Остановить сервер: Ctrl+C. Если изменили frontend, повторите `npm run build` и перезапустите сервер. В базовом режиме GPU, ключи API и внешние сервисы не нужны.

Linux/macOS: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.txt`; остальные команды аналогичны, Python запускается через `.venv/bin/python`.

Режим разработки: backend как выше; во втором терминале `cd frontend; npm run dev`. Vite проксирует `/api` на порт 8000. Не запускайте публичный сервер без авторизации, TLS, ограничений запросов и дискового пространства: текущая версия предназначена для одного доверенного пользователя на локальной машине.

## Что работает

- Автоулучшение: CLAHE для света, слабое подавление цветного шума, unsharp mask. Отдельно свет, резкость и шум. Это реальные алгоритмы OpenCV, а не нейросети.
- Деликатная ретушь: детектор фронтального лица OpenCV и слабый bilateral-фильтр внутри мягкой овальной маски, максимум 28% смешивания. Это не сегментация кожи: проверяйте глаза, волосы и мелкие детали. Если лицо не найдено, возвращается сообщение, а не имитация результата.
- Реставрация базовая: коррекция света, шума и резкости. Удаление царапин и восстановление утраченных деталей не реализованы этим фильтром.
- Масштабирование Lanczos 2×/4×, без генерации новых деталей. Real-ESRGAN подключается отдельно.
- Фото на документы: 35×45, 30×40, 50×50 мм при 300 DPI. Фото вписывается целиком, поля заполняются выбранным цветом. Это подготовка холста, не гарантия принятия ведомством: размер головы, фон, освещение и биометрию надо проверить отдельно. Для замены фона сначала подготовьте фото отдельной операцией и загрузите экспортированный результат.
- Минимальное вмешательство: только свет/улучшение с силой не более 25%, либо документный холст. Изменение лица, ретушь и генеративные операции заблокированы.
- Результат всегда получает новый ID; обработка берёт оригинал, не накапливает эффекты. Исходное соотношение сторон и полный кадр сохраняются, кроме явно выбранного документного холста, где добавляются поля. Прозрачность сохраняется; JPEG сводится на белый фон.
- ZIP содержит выбранное фото, либо все фото при включённой пакетной обработке. Ошибки отдельных файлов показываются; успешные результаты сохраняются. Для файлов с ошибкой экспортируется предыдущий результат или оригинал — проверьте превью перед экспортом.

## Удаление и замена фона (rembg / U2NET)

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ai.txt
# Необязательно: каталог уже скачанных весов
$env:U2NET_HOME = "$PWD\models\u2net"
# Предварительно загрузить модель и проверить ONNX (нужен Интернет):
.\.venv\Scripts\python.exe -c "from rembg import new_session; new_session('u2net')"
```

Перезапустите сервер. Выберите «Работа с фоном», удаление или замену цветом. Интенсивность управляет смешиванием альфа-канала; для полного удаления используйте 100%. Модель около 176 МБ, CPU требует времени. Загрузка идёт с официальных release-ресурсов rembg; сохраняйте проверку контрольной суммы и TLS. Если модель недоступна, приложение показывает сообщение. Статус в интерфейсе означает наличие зависимости, работоспособность подтверждается только обработкой. Оригиналы внешнему сервису не передаются.

## Real-ESRGAN и GFPGAN (дополнительный ML-профиль)

Эти адаптеры используют настоящие модели, без подмены обычным ресайзом. Они требуют отдельного совместимого Python/torch окружения; базовый Python 3.12 / NumPy 2 профиль не заявлен как совместимый со старыми basicsr. Рекомендуемый отправной профиль — Python 3.10, NumPy 1.26, torch 2.1.2 / torchvision 0.16.2 и версии `realesrgan==0.3.0`, `gfpgan==1.3.8`, `basicsr==1.4.2`. Для такого окружения используйте `python -m pip install -r requirements-ml.txt` вместо базового requirements. Зависимости с GPU подбираются под вашу CUDA. Этот профиль не проверен в текущей CPU-среде.

Скачайте `RealESRGAN_x4plus.pth` из официального проекта https://github.com/xinntao/Real-ESRGAN и `GFPGANv1.4.pth` из https://github.com/TencentARC/GFPGAN. Проверьте происхождение и опубликованные суммы до загрузки: PyTorch-веса должны быть доверенными. Установите переменные перед запуском:

```powershell
$env:REALESRGAN_MODEL = 'C:\models\RealESRGAN_x4plus.pth'
$env:GFPGAN_MODEL = 'C:\models\GFPGANv1.4.pth'
```

Real-ESRGAN использует тайлы 256, CPU поддерживается, но медленный. GFPGAN может менять детали лица: это отдельный явно выбираемый инструмент, запрещённый в официальном режиме. Уменьшайте интенсивность и проверяйте идентичность. Модели не скачиваются молча при установке базового приложения.

## Генеративное API: одежда и раскрашивание

На сервере задайте `GENERATIVE_API_URL` и `GENERATIVE_API_KEY`. `.env.example` — справка; `.env` автоматически не загружается. Ключ не попадает во frontend. В интерфейсе запуск этих двух функций сопровождается пояснением о передаче фото.

Контракт адаптера: HTTPS POST multipart/form-data; `Authorization: Bearer <key>`; файл `image`, поля `operation` (`clothes`/`colorize`), `prompt`, `intensity` (0–100), `preserve_identity=true`, `preserve_composition=true`. Ответ 200 — байты PNG/JPEG/WEBP исходных размеров, максимум 20 МБ. Таймаут 120 секунд. URL должен быть задан администратором, а не пользователем запроса. Для провайдера с JSON/base64 или асинхронными заданиями реализуйте шлюз под этот контракт в `apply_one`.

Без API функции возвращают явное сообщение. Сохранение лица — инструкция провайдеру, а не технически доказанная гарантия; результат надо проверять. Автоматическое распознавание изменений идентичности не реализовано.

## Архитектура

```
backend/app/main.py        REST API, хранение, пакетная обработка, API-адаптер, ZIP
backend/app/processing.py  чистые операции Pillow/OpenCV, адаптеры моделей
backend/tests/test_app.py  API и инварианты изображений
frontend/src/main.tsx      редактор, настройки, сравнение, пакетная обработка
frontend/src/style.css     тёмная тема и адаптивные состояния
storage/                  локальные нормализованные PNG, исключены из Git
```

`POST /api/upload`, `POST /api/process`, `POST /api/export`, `GET /api/capabilities`, `GET /api/images/{id}`, `GET /api/health`. Схемы в `/docs`. Операции обработки сериализованы семафором; OpenCV выполняется вне event loop. Это одно-процессный MVP, не распределённая очередь. Максимум входного фото 20 МБ/24 Мп, выход масштабирования 48 Мп. Метаданные EXIF удаляются, ориентация применяется; исходный пользовательский файл никогда не записывается. Приложение хранит нормализованный оригинал и результаты без автоматического удаления. Чтобы очистить, остановите сервер и удалите нужные PNG из `storage`; для промышленной эксплуатации нужны квоты, срок хранения, пользователи и очередь задач. Экспорт ZIP собирается в памяти; не используйте пакет из больших фото при недостатке RAM.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
cd frontend
npm run build
```

Тесты проверяют реальные вызовы обработки, размеры, альфа-канал, нулевую интенсивность, неизменность оригинала, ограничения, ZIP и недоступный API. Модельные тесты требуют отдельно установленных весов и не подменяются фиктивными ответами. Ручная проверка: загрузить фото, применить улучшение, сравнить ползунком, скачать ZIP и открыть результат.

В Windows также есть скрипты `scripts/setup.ps1` и `scripts/start.ps1`. При запрете PowerShell на выполнение скриптов используйте отдельные команды из начала README; менять глобальную политику выполнения не требуется.

`requirements-lock.txt` фиксирует фактически проверенное Linux/Python 3.12 окружение, включая rembg. Для Windows используйте основные requirements-файлы: lock включает платформенные пакеты Linux. Интерфейс не требует внешних шрифтов или CDN.

Проверка запущенного сервера: `.venv/bin/python scripts/smoke.py` (Windows: `.\.venv\Scripts\python.exe scripts/smoke.py`). Флаг `--with-model` выполняет настоящее удаление фона U2NET и проверяет прозрачность. Это создаёт локальные тестовые изображения в storage.

Проверено в текущей Linux-среде: 9 автоматических тестов прошли, production-сборка React/TypeScript прошла, HTTP-цепочка загрузка → обработка → ZIP прошла, настоящая U2NET-инференция сохранила размер и создала прозрачность. Real-ESRGAN, GFPGAN и внешний API здесь не проверялись. Windows-инструкции подготовлены, запуск на Windows в этой среде не выполнялся.
